Swapping the ego controller on four junction scenarios

IDM against the compiled behaviour tree, measured by collision occurrence over 8 runs on CARLA 0.9.16 / Town10HD_Opt.

What was run. Each of the four scenarios/benchmark scenarios was executed under two arms: once exactly as compiled, and once with the ego's actuation handed to an Intelligent Driver Model through the new --ego-policy entry point. Everything else — NPC timelines, spawn geometry, emit/wait events, the monitors that fire the adversarial triggers — is identical between arms; only the ego's controller changes. IDM ran with library defaults (v0=8.333 m/s, T=1.5 s, a_max=1.5 m/s², b=2.0 m/s², δ=4.0, s0=2.0 m) in all four scenarios, so no per-scenario tuning is hiding in the results. Each cell was repeated 20 times.

The metric

The measurement is collision occurrence on the ego's collision sensor, used as a proxy for whether the scenario still executed what it was written to exercise. The proxy is directional — it is not "fewer crashes is better":

  • the three crash scenarios have executed correctly when the ego is hit; a clean run means the scripted conflict never developed;
  • stop_sign has executed correctly when the ego is not hit.

So the raw proxy is collision_occurred == expect_collision. Running the experiment showed that this alone is too weak: a collision with the wrong vehicle scores as a pass. The report therefore also checks the striking vehicle's role_name against the scenario's scripted antagonist. The headline number below is that stricter intended-conflict rate; where the two diverge, the cell is annotated wrong-antagonist.

Measurement notes

  • Repeatability. Every cell above was unanimous across its 20 repeats — 20/20 or 0/20, never a split — so within this configuration the outcomes are repeatable and the rates are not hiding variance. One earlier video-recording run of left_turn scripted did produce no collision; it came from the session in which the CARLA server later crashed, and it did not reproduce in 20 clean repeats. Treat marginal conflicts as worth re-running rather than trusting a single sample.
  • Instrumentation is excluded. The benchmark scenarios place a ground-decal marker at each conflict point as a distance reference. CARLA does occasionally report a contact when the ego drives over it (6 of these 160 runs, all in left_turn under IDM), so the metric counts only vehicle-versus-vehicle contacts; static-prop contacts are recorded separately as n_static_contacts. Counting them would let a clean run register as a crash.
  • The NPCs have no driver model. drive() is a waypoint+PID controller that never yields and never brakes for anything. Any ego that deviates from the scripted timing therefore risks being rear-ended by its own scripted follower — which is exactly what happens in red_light under IDM. That is a property of the benchmark, not a defect in IDM, and it is the single biggest caveat on these numbers.
  • Lateral control is shared. IDM is longitudinal only; steering reuses the same pure-pursuit rule as the compiled drive(), so both arms follow the identical route through each junction and the comparison isolates the longitudinal policy.

Reproducing

./experiments/run_experiments.sh                                    # 8 recorded runs
REPEATS=20 ./experiments/run_experiments.sh results/repeats --no-video
python experiments/make_report.py                                   # rebuild this page

Requires a CARLA 0.9.16 server on port 2000 and the cp38 interpreter; the runner refuses to start on a Python that cannot import CARLA. A no-video run takes ~6 s, so the repeat sweep is cheap; recording video is what costs time.
