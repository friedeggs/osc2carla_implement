Swapping the ego controller on four junction scenarios

IDM against the compiled behaviour tree, measured by collision occurrence over 260 runs on CARLA 0.9.16 / Town10HD_Opt.

What was run. Each of the four scenarios/benchmark scenarios was executed under two arms: once exactly as compiled, and once with the ego's actuation handed to an Intelligent Driver Model through the new --ego-policy entry point. Everything else — NPC timelines, spawn geometry, emit/wait events, the monitors that fire the adversarial triggers — is identical between arms; only the ego's controller changes. IDM ran with library defaults (v0=8.333 m/s, T=1.5 s, a_max=1.5 m/s², b=2.0 m/s², δ=4.0, s0=2.0 m) in all four scenarios, so no per-scenario tuning is hiding in the results. Each cell was repeated 20 times.

The metric

The measurement is collision occurrence on the ego's collision sensor, used as a proxy for whether the scenario still executed what it was written to exercise. The proxy is directional — it is not "fewer crashes is better":

  • the three crash scenarios have executed correctly when the ego is hit; a clean run means the scripted conflict never developed;
  • stop_sign has executed correctly when the ego is not hit.

So the raw proxy is collision_occurred == expect_collision. Running the experiment showed that this alone is too weak: a collision with the wrong vehicle scores as a pass. The report therefore also checks the striking vehicle's role_name against the scenario's scripted antagonist. The headline number below is that stricter intended-conflict rate; where the two diverge, the cell is annotated wrong-antagonist.

Measurement notes

  • Repeats would be uninformative. The local backend is deterministic: three identical runs of left_turn produced bit-identical first-contact time, peak impulse, distance and event count, and sweep_idm_local.py --check-determinism asserts this before every sweep. The 64 runs per IDM cell are therefore 64 different parameter vectors, drawn from a Latin hypercube over the six IDM parameters, not 64 repeats. The scripted arm has no parameters and is a single deterministic run.
  • These rates measure fit to the staged timing, not safety. Each scenario was tuned so that the scripted ego arrives at the conflict when the scripted antagonist does. An IDM ego with different acceleration arrives at a different time, so a low intended-conflict rate mostly says the policy does not match the choreography — not that it drives badly. a_max being the strongest predictor in three of four scenarios is exactly this effect.
  • The NPCs have no driver model. drive() is a waypoint+PID controller that never yields and never brakes for anything. Any ego slower than the scripted one is rear-ended by its own scripted follower — which happens in 64/64 red_light runs and 59/64 left_turn runs. That is a property of the benchmark, not of IDM, and it is the single biggest caveat on these numbers.
  • stop_sign is the one clean read. It is the only scenario whose pass condition is the absence of a collision, so it does not depend on meeting a scripted antagonist on schedule. IDM fails it in 19 of 64 samples: it has no term for a crossing conflict, so whether it yields to the crosser is incidental — a consequence of car-following on a vehicle that happens to be ahead, not of giving way.
  • Six comparisons per scenario. The sensitivity tables split 64 samples at each parameter's median, six times per scenario. With that many comparisons an isolated 15-point gap is unremarkable; only a_max in left_turn (+56 points) is large enough that the 95% intervals of the two halves do not overlap.
  • Instrumentation is excluded. Each scenario places a ground-decal marker at its conflict point as a distance reference. The local simulator reports a contact when a vehicle drives over one but does not deflect the vehicle, mirroring CARLA; the headline metric counts only vehicle-versus-vehicle contacts, and decal contacts are reported separately as n_static_contacts.
  • Lateral control is shared. IDM is longitudinal only; steering reuses the same pure-pursuit rule as the compiled drive(), so both arms follow the identical route through each junction and the comparison isolates the longitudinal policy.
  • Geometry is synthesised. These scenarios run at the centre junction of the local grid town, not at Town10HD_Opt junctions 189/841/134. Absolute numbers are not comparable with the CARLA benchmark; the intended outcome per scenario is.

Reproducing

# 64-sample IDM parameter sweep + scripted reference (260 runs, ~1 min on 12 cores)
python experiments/sweep_idm_local.py -n 64 --seed 20260818 --jobs 12 --check-determinism
python experiments/make_report.py experiments/results_local_sweep \
    -c experiments/benchmark_local.json -o experiments/report_local/index.html

# single-sample run of both arms, with bird's-eye recordings
./experiments/run_experiments_local.sh

Needs pygame and nothing else: no CARLA, no GPU, no server, and no Python 3.8
constraint. A no-video run takes ~1.8 s. The sweep is reproducible from the seed:
the sampler is seeded and the simulator is deterministic, so the same seed gives
the same 64 parameter vectors and the same 260 results.
